# Operator vault

The agent's working notes, organised with PARA. Open this folder as an Obsidian vault if you like; plain Markdown works too.

| Folder | What goes in it |
|---|---|
| `Projects/` | One folder per active project: `Projects/<Project>/<Project>.md`, plus `Meetings/` and `Decisions/` inside it. A project has an outcome and an end. |
| `Areas/` | Ongoing responsibilities with no end date. `Areas/Reports/` holds the daily briefs, weekly and monthly reports; `Areas/Meetings/` holds meetings that belong to no project. |
| `Resources/` | Reference material worth keeping: how-tos, checklists, `Lessons.md`. |
| `Archive/` | Finished or cancelled projects, moved here whole by `project-closeout`. |
| `Templates/` | Note templates the skills use. |

Rules the agent follows here:

- One fact lives in one note; other notes link to it with `[[Note Name]]`.
- Dates are `YYYY-MM-DD`. File names start with the date for meetings, decisions and reports.
- Task status lives in the system of record. If that is this vault, it is the checklist in each project note.
- Nothing is deleted. Closed work moves to `Archive/`.
- This vault holds real project data. Do not commit it to the public template repository.
